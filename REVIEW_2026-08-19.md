## 2. Tech Lead lens

### 🔴 Blocking

- **Sandbox dead on prod (3 independent gaps)**: `docker-compose.prod.yml:70` runs `entrypoint: ["sandboxd"]` but the pushed image (`backend/Dockerfile`) builds only `./cmd/server` → crash-loop. - **Public data exposure**: `migrations/016` `public_active_jobs_lookup`/`public_job_detail_lookup` filter only `status='active'`; no API can set `is_published` — every job (active by default) is instantly public with salary + applicable.
- **Broken feature**: `rubric_worker.go:44` — `GetByID`/`Update` without tenant tx → `db.ErrNoTx` → every `generate_rubric` task retries and dead-letters.
- **Auth/security**: `jwt_provider.go:50` `Parse` lacks `WithExpirationRequired()` + issuer check → tokens without `exp` valid forever. `ratelimit.go:38` fails OPEN on Redis errors (auth brute-force protection gone during blips). `main.go:307` `tenantRateLimit` registered before `authMW` → dead; public jobs have no per-IP limit.
- **Tests that lie**: `check-coverage.sh` parser ignores bare `coverage: 0.0%` lines → six packages (email/rubric/sync workers, sandbox service+client, context service) invisible to the gate at 0%. `UpdateDecision` transitions, OTP lockout (5-attempt/429/replay), email worker SkipRetry have zero tests.

### 🟡 Important

- **FE**: `Candidates.tsx:109` drawer effect re-opens on every 2s poll + toast spam; `Jobs.tsx` stage-pipeline modal config silently discarded; `Dashboard.tsx:48` probes `/api/v1/ready` (route is `/ready`) → never green; no route code-splitting (992KB chunk to the public landing page); `tsconfig` `strict` off (violates AGENTS.md); `Careers.tsx` silent `DEMO_JOBS` fallback hides outages and demo applies 404; `CandidateReview.tsx` sets state in `queryFn` (refetch overwrites edits); clipboard calls unhandled; CodingSandbox modal not a real dialog (no focus trap/Escape).

## 4. CEO lens

### 🔴 Business-killers

- **Candidate emails dead in prod** — kills the product, not a feature. Real transactional provider (Resend/SES/Brevo) + delivery assertion + remove mailpit from prod.
- **Every active job public with apply+CV-LLM flow and no publish control** — recruiters discover via their first Google hit. Commit the gate, default `is_published=false`, FE toggle.
- **Headline interview features don't run in prod**: sandbox (3 gaps), rubric worker writes a nonexistent column, CI smoke skips the core flow and isn't a deploy gate.
- **Backup/DR is theater**: no cron, single copy on the same disk (D5), restore can't rebuild the `intivai_app` role/RLS. Treat the 2026-09-30 offsite deadline as a hard customer gate.
- **Fabricated AI data shown to recruiters** — liability; fail honest ("not evaluated") instead of a number.

### 🟡 Important

- **Costs unbounded under provider outage**: asynq default `MaxRetry=25`, each retry re-invoking DeepSeek — day-long outage multiplies spend 25× with no cap/ledger/alert. Set `MaxRetry(5)` + per-org daily token cap + retry-storm alerting.
- Single VPS: app as root (no USER/read-only), only app mem-limited (sandbox bursts 512m each), concurrent runs can OOM the box; root-app compromise negates RLS.
- No token/cost ledger → can't answer "what does this customer cost me" or enforce a ceiling.
- No GDPR export/delete endpoints, no retention policy, no DPA/RLS evidence pack.
- No SLA/observability story: no uptime metric, no queue-depth/worker-death alert, no runbook.

### 🟢 Nits

Public apply is an unauthenticated LLM-spend + spam vector (per-IP limit now). Deploy is a one-way door (prunes old tags — keep last N + documented rollback). Drop whisper from prod until voice ships. 14-day backup retention vs legal retention unset.

### Verdict

**No paying customer today.** Business-killers are a deployment/integration problem, not a product problem: the code exists, is tested, and is one disciplined release pipeline away from working. Cost structure fine at beta (~$0.03/interview); the risk is unbounded retry spend, fixable in an afternoon. Recommended: one hardening sprint — commit everything, real SMTP, working sandbox + smoke + restore proven on a fresh VPS — then take the first paying customer.

## 5. HR Recruitment Specialist lens

### 🔴 Fairness / defensibility / candidate experience

- **Degree-ism at the auto-gate** (`scoring.go:125`): PhD=1.0, missing/unparsed degree=0, certifications binary — self-taught and OCR-truncated resumes silently lose the 10% education weight. Neutral default (0.5) + verify OCR coverage.
- **Empty dimensions score 0** (`report.go:68-77`): candidates never asked a culture-fit probe are penalized as if they failed it. Neutral-fill or require per-dimension minimums.
- **LLM recommendation unvalidated/uncalibrated** (`evaluator.go:87`): one hallucinated run becomes a hire/reject verdict. Enum check + consistency sampling + rater-agreement stats.
- **30-QA window** scores long interviews on the tail only — early answers never count.
- **Consent doesn't disclose monitoring** (Invite.tsx:85): tab-switch/paste/audio telemetry collected under "answers being analyzed"; coerced (only path to the interview). Disclose fully + offer a monitoring-free alternative.
- **Ghosted candidates**: `"candidate_review"` email silently dropped (unknown type + hardcoded `localhost:5173` URL); no rejection/offer emails; failed screeners see "in progress" forever; portal exposes a number with no rationale (no right to explanation).
- **Fabricated profile facts**: `?? 3 years`, hardcoded skill list, canned screening recommendation rendered as real.

### 🟡 Important

- Proctoring is client-reported, silently droppable (`.catch(()=>{})`), yet shown as exact penalties with no human review step — label "unverified" + flag-review workflow.
- Terminal stages are one-way doors (recruiter can't reverse `rejected` without admin; drawer doesn't even offer `screening_failed`).
- PDF-only apply (no structured form/DOCX/LinkedIn) — excludes mobile/no-PDF applicants.
- Skills match is exact-token (K8s ≠ Kubernetes); experience is a hard ratio — near-miss candidates lose at the gate that decides who is interviewed.
- OTP endpoint emails any address (60s cooldown only) — distributed spam vector; enqueue errors swallowed.
- Job listings are skeletal: salary/location/employment-type collected but never shown, contradicting the "transparent salary ranges" promise.
- Candidate JWT lives 7 days in localStorage; 5-attempt lockout untested.

### 🟢 Nits

"Share" scorecard URL is auth-gated; PDF scorecard repeats the integrity fabrication ("Spotless Session").

### 🎉 Strengths

PDF scorecard with verbatim quotes + rationale is genuinely defensible audit documentation (surface the same evidence on-screen). Post-application "what happens next" messaging is clear. Transcript a11y (`role="log"` + `aria-live`, text-plus-color timers) is decent.

### Verdict

**Would not run a real hiring pipeline on it today.** The concept genuinely saves hours and the evidence trail is well designed, but the product shows recruiters and candidates numbers, rationales, and integrity scores that were never computed, and auto-gates candidates on a model with degree-ism and OCR fragility. Pilot with humans making every decision and all AI output labeled advisory. Fix the fabrications, wire the dead email flows, disclose the surveillance — "the bones are good."

## 6. Aggregated verdict & action sequence

🔄 **Request changes — all four lenses agree the product is one disciplined sprint from sellable; the single biggest risk is the uncommitted review round itself.**

1. **Commit the working tree in logical commits** — gate 14; nothing else matters until this is true
2. **Sandbox on prod**: images → ghcr, certs in deploy, sandboxd in image, code.run round-trip in smoke
3. **Kill mailpit in prod** → real SMTP provider + delivery assertion + OTP e2e
4. **`is_published` gate + FE publish toggle** (fixes both exposure and empty-board outcomes)
5. **Delete every fabricated value**: fake 85, fake integrity (UI + PDF), canned rationale, hardcoded AI review — render honest "no data/unavailable" states
6. **CI**: fix smoke port, inject DeepSeek key, make smoke a deploy gate, `set -e` + `permissions:` + no sed-rewrite of tracked compose
7. **Cost rails**: `MaxRetry(5)` per task, token ledger at the LLM port, per-org daily cap
8. **HR fairness**: neutral-fill empty dimensions, degree default 0.5, recommendation validation, consent disclosure, decision emails, right-to-explanation in the portal
9. **DR**: cron + offsite (hard gate 2026-09-30), restore role bootstrap, monthly restore test

After items 1–5, re-run all four lenses. The product core (tenant isolation, WS protocol discipline, scorecard evidence trail) is genuinely strong and worth the sprint.
